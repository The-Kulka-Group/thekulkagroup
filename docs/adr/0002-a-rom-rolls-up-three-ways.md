# A ROM rolls up three ways, not two

We store every cost at the canonical work item and roll it up to CSI division for
estimators, to element for developers, and to buyout package for anyone defending a
number. The working-session packet framed this as division against element. Reading the
Autodesk contract reports added the third axis.

Kulka buys out by package, and a package cuts across divisions. On Jefferson's Ferry,
Evian's "Siding and Masonry" subcontract lands in Division 04 and Division 07. On
Fieldstone, All Island's "Site Work" package spans earthwork, utilities and paving. That
matters because of how an estimator checks a figure: asked whether a framing number is
right, they recall what a subcontractor signed, not what a division totalled. The package
is the unit of memory and the unit of defence.

## Consequences

Three rollups need a maintained mapping from canonical work item to element and to
package. Packages are the awkward one, because a package maps to several work items and
needs a stated allocation rather than a lookup.
