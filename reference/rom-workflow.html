Intake

~20 min
The estimator answers what only a person can know Estimator Live

  1. Pick the project and how deep to go.

    A tier sets how many questions get asked; a fast pass for an early number, deeper tiers when more is known.

  2. Answer the fixed set of intake questions.

    Unit count, stories, construction type, parking type, and the handful of gates — gas building, roof type, HVAC system — that actually change what gets priced.

  3. Confirm or correct what the tool already worked out.

    Where a fact can be derived from another one already given — elevator stops from stories, for instance — the tool proposes it; the estimator just confirms or overrides it.

PRODUCES A dated project record — every answer, every gate, ready to price. kulka-budget-questions
W-200

Engineer

seconds
The tool works out what a real engineer would, before one is ever on the job AI Building

  1. Size the real MEP and life-safety numbers.

    Electrical service size off NEC load tables, insulation off IECC climate-zone tables, HVAC tonnage off a square-foot-per-ton rule, elevator type off travel distance, sprinkler system type off construction and stories.

  2. Show the math, not just the number.

    Every derived value carries the code section or method behind it, so it reads as an engineering fact, not a guess dressed up as one.

  3. Only reach outside the building when nothing captured already answers it.

    Two gates — emergency responder radio coverage, fire alarm notification type — genuinely turn on local code, not on anything the tool already knows.

A jurisdiction lookup has to run first

The AI judgment layer this leans on can only judge text it’s handed — it has no lookup of its own. Until that retrieval step exists, those two gates fall back to asking the estimator outright.

PRODUCES A labeled set of engineering criteria, dated, sourced, ready to price against. design criteria panel
W-300

Blend & range

seconds
Real cost data sets the price — nothing is priced on AI judgment alone AI Not started

  1. Pull every real comparable for this line.

    Actual bought costs first, vetted benchmark budgets second, an AI signal last — and only ever one voice among real data, never alone.

  2. Tighten the range as real evidence grows.

    More comparables narrow the spread and sharpen the range; few or noisy comparables keep it wide on purpose, not by accident.

  3. Flag every line’s confidence, and name why.

    High, medium, or low — driven by comparable count, spread, and kind — and the flag names the comparables behind it, so it’s never a black box.

A mis-tagged cost row must never become a benchmark

A line that’s really a takeoff helper or a duplicate is excluded before it can reach a benchmark. One that got through once already threw a real benchmark off by two orders of magnitude.

PRODUCES A ranged budget, line by line, every range showing its own confidence. ROM engine

The range is set. Now a person checks it.

Review

minutes
Nothing reaches a client until a person has looked at what changed Kulka Live

  1. Anything imported gets staged before it counts.

    A new cost file sits in a holding queue first; nothing becomes a benchmark until someone approves it, so one bad import can’t silently corrupt a live number.

  2. A held line gets a second look, by name.

    A low-confidence or newly-changed line is flagged right on the budget itself, not buried in a log somewhere else.

  3. Every assumption is written in plain English, on the sheet.

    If the tool assumed a rate, a system type, or a pricing driver, that assumption prints right there — not hidden inside the math.

A repeat import is skipped, not blended

Re-importing the same cost code doesn’t yet blend with what’s already there — it’s skipped on purpose, until real blending logic exists, so a re-import can never quietly double a number.

PRODUCES An approved, defensible ranged budget, with its assumptions in writing. ingestion gate
W-500

Issue

at closing
The budget goes out, and the real numbers come back to make the next one better Kulka Building

  1. Issue the budget against a real, named project.

    The ROM is linked to the actual job it’s for, not left floating on its own.

  2. Compare it against what the job actually cost, once it closes.

    Award-to-final and award-to-bought-out gaps get measured, not guessed at.

  3. Feed that gap back into the tool’s own stops.

    The dial that tightens future ranges is built entirely from Kulka’s own measured history — never a made-up fudge factor.
